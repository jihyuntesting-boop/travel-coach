# AI 코딩 도구 사용 기록

- 사용 도구: Claude Code (클라우드 세션)
- 이 문서는 작업 과정에서 실제로 있었던 일을 요약한 기록입니다. 원문 대화 화면 캡처는 별도로 첨부합니다.

## 1. 기획과 구현
| 단계 | 사용자 요청 | AI 작업 |
|---|---|---|
| 기획 | 과제 원문 전달, 서비스 아이디어 선택 | "연구질문 코치"로 확정하고 기획서(docs/plan.md) 작성 |
| 구현 | 프론트와 백엔드 구현 | 바닐라 HTML/CSS/JS, `api/` Python 함수, 단위 테스트 12개 작성 |
| 검증 | 로컬 동작 확인 | 로컬 서버로 빈 입력(400), 키 없음(500), GET(405) 응답과 모바일 가로 스크롤 없음을 확인 |
| 공급자 변경 | Claude API 대신 Gemini 키를 쓰겠다고 요청 | 호출부를 Gemini REST로 교체, 환경 변수명을 `GEMINI_API_KEY`로 변경, 문서 갱신 |

## 2. 오류가 발생해 원인을 찾아 고친 과정
AI가 만든 코드와 설정에서 실제로 난 오류와 수정 내용입니다.

1. **`PYTHON_ENTRYPOINT_NOT_FOUND` (Vercel 배포 실패)**
   - 증상: 빌드가 "No python entrypoint found in default locations"로 실패했습니다.
   - 원인 추정: 루트의 `requirements.txt` 때문에 Vercel이 프로젝트를 Python 앱으로 자동 인식했습니다.
   - 수정: `vercel.json`에 `"framework": null`을 넣어 `api/` 함수만 사용하게 했습니다.
2. **배포 후 "서버 설정이 완료되지 않았습니다" (HTTP 500)**
   - 증상: 화면은 뜨지만 AI 호출이 실패했습니다.
   - 원인: 배포 환경에 `GEMINI_API_KEY`가 반영되지 않았습니다. 환경 변수는 저장 후 재배포해야 반영됩니다.
   - 조치: 환경 변수 이름, 적용 환경(Production), 재배포 여부를 점검한 뒤 재배포했습니다.
3. **"AI 서비스 호출에 실패했습니다" (HTTP 502)**
   - 증상: 키를 읽은 뒤에도 Gemini 호출이 실패했습니다.
   - 원인 추정: 기본 모델 `gemini-2.5-flash`가 종료 예정이라는 검색 자료가 있었습니다(자료마다 날짜가 달라 확정은 못 함).
   - 수정: 기본 모델을 별칭 `gemini-flash-latest`로 바꾸고, 호출 실패 원인이 서버 로그에 남도록 했습니다. 수정 후 HTTP 200으로 정상 응답했습니다.

## 3. 직접 이해하고 설명할 수 있는 수정 방향
- 프론트 검증은 편의용이고, 서버 검증이 실제 방어선입니다.
- API 키는 서버(Vercel 환경 변수)에서만 읽고 코드, README, 스크린샷에는 넣지 않습니다.
- 환경 변수를 바꾸면 재배포해야 반영됩니다. 오류는 Vercel Logs와 HTTP 상태 코드로 층(프론트, 서버, 외부 API, 설정)을 나눠 추적합니다.
